# Connector ownership registry

Kashier and EasyKash are independent Git submodules. The platform repository tracks their commit pointers, not their source files. The combined release targets official Hyperswitch `83cc4876dd067ff16bcac51ce2737ee0fe0bf8b1` (`v1.126.0`) and Control Center `adc307d08c87862380f966af44b849ddfee21dcc` (`v1.38.8`). Neither connector is a dynamically loaded plugin. Source registration and local packaging do not change the separately managed production service.

| Connector | Authoritative repository | Pinned commit | Integration boundary |
| --- | --- | --- | --- |
| Kashier | [hyperswitch-kashier-connector](https://github.com/Byt3Ninja/hyperswitch-kashier-connector) | `10f0957a1d1cd9342bed25d41869c8c0a5a60c7f` | Apply its backend and dashboard patches first. Presence here is not deployment approval. |
| EasyKash | [hyperswitch-easykash-connector](https://github.com/Byt3Ninja/hyperswitch-easykash-connector) | `50baf0d196cb4e6726bd6b786e6e305260ac2fbe` | Apply its `after-kashier` backend and dashboard deltas second. No live payment readiness claim. |

Do not copy connector source into the parent repository. Connector repositories own provider behavior and reviewed integration patches; this parent owns release packaging and source-contract checks. The official `hyperswitch/` checkout stays unmodified. `deployment/coolify/production/connectors/build-release.sh` applies the approved parent-owned Santander compatibility patch to the fresh pinned backend source, then the reviewed connector patches in their unchanged order, Kashier then EasyKash. Dashboard order remains Kashier then EasyKash. Any further shared Hyperswitch changes need their own Category E review.

Run `deployment/coolify/production/connectors/build-release.sh --validate-only` for offline source-pin, clean-state, gitlink, manifest, runtime-digest, patch-application, and registry checks. It creates and cleans a temporary backend integration tree; it does not build binaries or images, fetch dashboard source, authenticate, or contact running services. Both connectors must appear in `Connector` and `RoutableConnectors`, including both conversion directions. A feature-matrix entry alone is insufficient: the observed production router advertised Kashier while its routing enum rejected it.

For a local release build, pass an absolute, nonexistent output directory whose parent exists, for example `/tmp/openswitch-combined-release`. The host needs Python 3.11+, Git, and Docker with Linux amd64 execution support. The parent and three child inputs must be clean at the reviewed pins. The script fetches the exact official dashboard revision and applies its ordered patches. All compilation and connector/dashboard checks run inside `builder/Dockerfile`: immutable amd64 official Rust 1.85.0 and Node 22.14.0 image digests, Rust 1.85.0 rustfmt/Clippy, and native packages from the signed Debian bookworm archive at `20250320T000000Z`. No host compiler, native library, Cargo/npm cache, or Docker socket is mounted into the builder. Cargo uses `--locked`, npm uses `npm ci`; generated sources use a fixed `/build` path and standalone Git objects. Compiler/library inputs are controlled by this reviewed recipe, and its resulting immutable builder image ID is used for execution and included in every release tag and release record. Different builder images cannot overwrite the same release tags. Bit-for-bit artifact equality is not asserted without a repeated-build comparison.

Packaging copies only release binaries or dashboard `dist/` over the four digest-pinned Kashier runtime references. It preserves runtime libraries, users, commands, entrypoints, and configuration mount behavior. Router is separate; producer and consumer share the scheduler binary but retain their respective upstream image roles. Before writing `release.json`, the validator executes `router --version` and `scheduler --version` inside the exact built router, producer, and consumer image IDs with `LD_BIND_NOW=1`, no network, a read-only filesystem, dropped capabilities, and no additional privileges. This validates dynamic-library loading against the actual pinned runtimes; any failed probe blocks the release record. The non-secret record includes source pins, patch order, parent commit, builder image ID, successful runtime-check roles, binary checksums, and local image IDs/tags. Local image IDs are not registry manifest digests; publication must later record those separately.

The official `crates/connector_configs/toml/production.toml` baseline contains a Santander duplicate `name` key. The user-approved temporary patch in `deployment/coolify/production/connectors/compatibility/santander-metadata.patch` inserts only the missing `[[santander.metadata.pix_automatico_push]]` header before the affected `name="pix_key_type"`. The parent owns this compatibility patch; it is applied only to generated integration source, never the official submodule or connector repositories. Validation requires the exact clean official commit and exact one-line patch, rejects drift or expanded scope, and parses the complete repaired TOML before connector integration. Full metadata validation remains mandatory after integration. Remove this patch and its application guard when a separately reviewed upstream source pin includes the equivalent fix; a source upgrade must fail closed until that review. Strict Clippy may still encounter upstream warnings documented in the EasyKash kit. Those require separate upstream resolution/review; do not bypass them.

The live deployment gate remains required. Images contain no credentials, route state, or endpoint overlay. The desired-state contract requires Kashier `https://test-api.kashier.io/` for all four sandbox profiles; current live-provider configuration must be reviewed and changed separately through the approved deployment packet. EasyKash remains the WQ3 Sandbox low-risk live-provider pilot, with explicit MCA selection and no default route. No database or migration changes are part of packaging. Rollback of a later approved deployment restores its recorded previous images/configuration; packaging alone makes no service changes.
