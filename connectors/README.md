# Connector ownership registry

Kashier and EasyKash are independent Git submodules. The platform repository tracks their commit pointers, not their source files. The combined release targets official Hyperswitch `83cc4876dd067ff16bcac51ce2737ee0fe0bf8b1` (`v1.126.0`) and Control Center `adc307d08c87862380f966af44b849ddfee21dcc` (`v1.38.8`). Neither connector is a dynamically loaded plugin. Source registration and local packaging do not change the separately managed production service.

| Connector | Authoritative repository | Pinned commit | Integration boundary |
| --- | --- | --- | --- |
| Kashier | [hyperswitch-kashier-connector](https://github.com/Byt3Ninja/hyperswitch-kashier-connector) | `10f0957a1d1cd9342bed25d41869c8c0a5a60c7f` | Apply its backend and dashboard patches first. Presence here is not deployment approval. |
| EasyKash | [hyperswitch-easykash-connector](https://github.com/Byt3Ninja/hyperswitch-easykash-connector) | `50baf0d196cb4e6726bd6b786e6e305260ac2fbe` | Apply its `after-kashier` backend and dashboard deltas second. No live payment readiness claim. |

Do not copy connector source into the parent repository. Connector repositories own provider behavior and reviewed integration patches; this parent owns release packaging and source-contract checks. The official `hyperswitch/` checkout stays unmodified. `deployment/coolify/production/connectors/build-release.sh` applies the reviewed patches to fresh generated source directories, always Kashier then EasyKash. Any further shared Hyperswitch changes need their own Category E review.

Run `deployment/coolify/production/connectors/build-release.sh --validate-only` for offline source-pin, clean-state, gitlink, manifest, runtime-digest, patch-application, and registry checks. It creates and cleans a temporary backend integration tree; it does not build binaries or images, fetch dashboard source, authenticate, or contact running services. Both connectors must appear in `Connector` and `RoutableConnectors`, including both conversion directions. A feature-matrix entry alone is insufficient: the observed production router advertised Kashier while its routing enum rejected it.

For a local release build on x86_64 Linux, pass an absolute, nonexistent output directory whose parent exists, for example `/tmp/openswitch-combined-release`. Build dependencies include Python 3.11+, Git, Rust/Cargo with rustfmt and Clippy, Node/npm, Docker, PostgreSQL/OpenSSL/protobuf development packages, pkg-config, and protoc. The parent and three child inputs must be clean at the reviewed pins. The script fetches the exact official dashboard revision, applies its ordered patches, runs connector and dashboard checks, builds router/scheduler and `dist/`, and packages four local versioned images. Cargo uses `--locked`, npm uses `npm ci`. Source/runtime pins are reproducible; compiler/toolchain versions must also be controlled by the release builder before claiming byte-identical artifacts.

Packaging copies only release binaries or dashboard `dist/` over the four digest-pinned Kashier runtime references. It preserves runtime libraries, users, commands, entrypoints, and configuration mount behavior. Router is separate; producer and consumer share the scheduler binary but retain their respective upstream image roles. The non-secret `release.json` records source pins, patch order, parent commit, binary checksums, local image IDs and tags. Local image IDs are not registry manifest digests; publication must later record those separately.

Known release blocker: official `crates/connector_configs/toml/production.toml` contains an unchanged Santander duplicate `name` key. Validation reports this baseline defect, parses the remaining metadata diagnostically, and does not claim whole-file validity. Full build mode stops on it before compilation or image builds. The source is never repaired or stripped. Strict Clippy may also encounter the upstream warnings documented in the EasyKash kit. These require separate upstream resolution/review; do not bypass them.

The live deployment gate remains required. Images contain no credentials, route state, or endpoint overlay. The desired-state contract requires Kashier `https://test-api.kashier.io/` for all four sandbox profiles; current live-provider configuration must be reviewed and changed separately through the approved deployment packet. EasyKash remains the WQ3 Sandbox low-risk live-provider pilot, with explicit MCA selection and no default route. No database or migration changes are part of packaging. Rollback of a later approved deployment restores its recorded previous images/configuration; packaging alone makes no service changes.
