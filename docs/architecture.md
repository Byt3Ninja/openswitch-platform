# OpenSwitch platform boundaries

OpenSwitch-platform is the outer orchestration repository. The hyperswitch/ gitlink pins official Hyperswitch commit `83cc4876dd067ff16bcac51ce2737ee0fe0bf8b1` (`v1.126.0`). This source pin is not a deployed-version claim. Router, connectors, scheduler, drainer, migrations, and upstream configuration remain in the child repository. Do not copy child files into the outer repository. Deployment remains gated on release-note, migration/config compatibility, tests, staging, readiness, and rollback evidence.

The outer repository can own deployment definitions, safe environment overlays, connector registry metadata, adapter references, and operational docs as actual requirements arise. The Coolify directories currently document staging and production separation; they are not live manifests. A customer-specific adapter should call supported Hyperswitch APIs rather than change generic payment logic. Connector code belongs in its authoritative repository; shared Hyperswitch integration changes need independent upstream-impact classification and possibly Category E approval.

The existing sibling OpenSwitch checkout has uncommitted Kashier code and shared registration edits. It is not the child submodule source. Its origin URL currently names the outer platform repository, so it must not be pushed there. Resolving Kashier ownership and any core approval is a separate task.

The authoritative Kashier and EasyKash repositories own their custom connector patches. The parent owns the combined release contract and four runtime wrappers in `deployment/coolify/production/connectors/`. Backend integration first applies the user-approved one-line Santander metadata compatibility patch to the clean pinned official source; backend and dashboard connector integration then applies Kashier followed by EasyKash. The checked-out upstream submodule remains clean. See [connector ownership and packaging](../connectors/README.md) for exact pins, commands, temporary compatibility ownership/removal conditions, and the sandbox endpoint boundary.

The release gate checks both broad connector and routable connector registration and both mapping directions. It rejects the observed partial deployment state where `/feature_matrix` advertises Kashier but the routing enum rejects it. Full compilation and artifact packaging remain additional gates; source validation alone cannot establish runtime or payment readiness. The only additional approved upstream source change is the one-line Santander metadata header in generated integration source. Packaging introduces no migrations, MCA records, routing changes, production configuration, or live actions. Reviewed connector patches include their previously approved shared registration changes only.
